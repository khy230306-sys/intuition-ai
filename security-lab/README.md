# 🏫 보안 실습실: 만들고 → 뚫고 → 막고 → 감시하기

이 실습은 **읽는 공부가 아니라 직접 해 보는 공부**를 위한 곳이에요.
로그인 서버를 **일부러 뚫리게** 만들고, 직접 **뚫어 본 다음**, 같은 기능을 **안전하게 고쳐** 보고, 마지막으로 **공격 흔적을 찾아내는** 도구까지 만들어요.

> ⚠️ **약속 3가지**
> 1. 이 실습의 서버는 **내 컴퓨터(127.0.0.1)에서만** 돌아가요.
> 2. 공격 도구는 `127.0.0.1` / `localhost` 말고는 요청을 보내지 않아요 (안전장치).
> 3. 실제 남의 사이트, 회사 서버, 학교 서버에 이 기술을 쓰면 **불법**이에요. 허락받은 곳에서만!

필요한 것: **Python 3만 있으면 돼요.** 외부 패키지 설치는 필요 없어요.

---

## 📁 파일 지도

| 파일 | 역할 | 비유 |
|---|---|---|
| `vulnerable_app.py` | 일부러 뚫리게 만든 로그인/검색 서버 | 문에 자물쇠를 안 채운 집 |
| `attack_sqli.py` | SQL 인젝션 공격 도구 | 도둑의 '뒷문 찾기' 연습 |
| `attack_bruteforce.py` | 비밀번호 찍어 맞히기 도구 | 열쇠를 하나씩 돌려 보기 |
| `secure_app.py` | 같은 기능을 안전하게 고친 서버 | 자물쇠, 경보기, 출입 기록을 갖춘 집 |
| `log_monitor.py` | 공격 흔적을 찾는 감시 도구 | CCTV 보는 경비원 |
| `test_lab.py` | 위 내용이 실제로 맞는지 자동 검사 | 시험 채점기 |
| `common.py` | 비밀번호 해시, DB, 로그 공통 기능 | 공구함 |

## 🪜 단계별 실습 순서

### 1단계: 취약한 서버를 '관찰'하기 (10분)

터미널 1에서 서버를 켜요.
```bash
cd security-lab
python3 vulnerable_app.py --port 8001
```
(끄려면 `Ctrl + C`)

이제 `vulnerable_app.py`를 열고 **`❌ 취약점 #번호`** 주석 4개를 찾아 보세요.

- **#1 SQL 인젝션**: 사용자가 쓴 글자를 SQL 문장에 그대로 붙여 넣어요.
- **#2 정보 노출**: 오류가 나면 SQL 문장 전체를 화면에 보여 줘요.
- **#3 무제한 시도**: 틀려도 계속 시도할 수 있어요.
- **#4 비밀번호 평문 저장**: 비밀번호를 그대로 DB에 넣어요.

> 🧒 **쉬운 말로:** 우리 집 열쇠 보관함에 "열쇠 번호: 1234"라고 적어 두는 것과 같아요.

### 2단계: 직접 뚫어 보기 (핵심!)

터미널 2에서 공격 도구를 실행해요.
```bash
cd security-lab
python3 attack_sqli.py
python3 attack_bruteforce.py
```

**확인할 것**
- 로그인 우회: 비밀번호를 몰라도 `admin`으로 들어가요.
- 검색 창에서 `UNION`으로 **모든 사용자의 비밀번호**가 보여요.
- 따옴표 하나만 넣어도 **SQL 오류 메시지**가 나와요. 이건 공격자에게 힌트가 돼요.
- 흔한 비밀번호 목록을 돌리면 `sunshine`(alice의 비밀번호)이 뚫려요.

> 🧒 **쉬운 말로 SQL 인젝션:** 가게 주문서에 "치킨 한 마리 **그리고 계산대 돈 전부 주세요**"라고 몰래 써 넣는 것과 같아요. 점원(프로그램)이 주문서를 글자 그대로 믿어 버리는 거예요.

### 3단계: 같은 공격을 안전한 서버에 해 보기

터미널 1에서 취약한 서버를 끄고(`Ctrl + C`), 보안 서버를 켜요.
```bash
python3 secure_app.py --port 8002
```

그다음 터미널 2에서 같은 공격을 해 보세요.
```bash
python3 attack_sqli.py --target secure
python3 attack_bruteforce.py --target secure
```

**확인할 것**
- SQL 인젝션 입력은 **'입력 형식이 올바르지 않습니다'**로 막혀요.
- 비밀번호 찍어 맞히기는 **5번 틀리면 429(차단)** 가 나와요.

**`secure_app.py`와 `vulnerable_app.py`를 나란히 열어 비교해 보세요.** 같은 기능인데 달라진 부분이 6가지 있어요.

| 달라진 점 | 왜 필요할까? |
|---|---|
| 입력을 `?` 자리에 따로 넣기 | 글자가 명령어로 바뀌지 못하게 해요 |
| 허용된 글자만 받기 | 이상한 글자가 아예 들어오지 못해요 |
| 비밀번호를 해시로 저장 | DB가 털려도 원래 비밀번호를 알기 어려워요 |
| 실패 5번이면 5분 차단 | 찍어 맞히기가 불가능에 가까워져요 |
| 오류는 짧게 | 공격자에게 힌트를 주지 않아요 |
| 보안 헤더 추가 | 브라우저가 응답을 멋대로 해석하지 못하게 해요 |

> 🧒 **쉬운 말로 해시:** 비밀번호를 **믹서기에 갈아서 지문만 저장**하는 것과 같아요. 지문으로는 누가 그 음식을 만들었는지 알 수 있어도, 지문만 보고 원래 재료를 되돌릴 수는 없어요.

### 4단계: 공격 흔적을 찾는 경비원 만들어 보기 (방어자 관점)

공격을 받았던 서버의 기록(로그)을 감시 도구로 분석해요.
```bash
python3 log_monitor.py data/vulnerable.log   # 뚫린 서버 기록
python3 log_monitor.py data/secure.log       # 막은 서버 기록
```

**확인할 것**
- 보안 서버 로그에도 **공격 흔적은 그대로 남아요.** 막혔어도 기록은 있어야 해요!
- `log_monitor.py`의 `SQLI_PATTERN`(탐지 규칙)과 `FAILED_LOGIN_THRESHOLD`(실패 기준 5회)를 바꾸면 탐지 결과가 어떻게 달라지는지 실험해 보세요.

> 🧒 **쉬운 말로:** 집에 도둑이 들어왔는데 CCTV가 기록을 남겼다면, 도둑이 **성공했든 못 했든** 우리는 그 사실을 알 수 있어요.

### 5단계: 자동 시험으로 검증하기

```bash
python3 -m unittest -v test_lab
```
10개 테스트가 모두 `OK`여야 해요. 테스트가 확인하는 것:
- 취약한 서버는 **뚫리고**, 보안 서버는 **막히는지**
- 비밀번호가 **평문으로 저장되지 않는지**
- 감시 도구가 공격을 **제대로 찾아내는지**

## 🛠️ 도전 과제 (직접 고쳐 보기)

난이도 순서대로 골라서 해 보세요. 코드를 바꾸고 `test_lab.py`에 **테스트 한 줄을 추가**하면 가장 좋은 공부가 돼요.

1. **⭐ 쉬움: 탐지 규칙 추가하기** — `log_monitor.py`에 "비밀번호에 `<script>`가 들어오면 경고" 규칙을 추가해 보세요.
2. **⭐⭐ 보통: 시간 창 넣기** — 지금은 "총 5번"을 세는데, **"1분 안에 5번"**으로 바꿔 보세요. (기록에 있는 `time` 값을 쓰면 돼요.)
3. **⭐⭐ 보통: 계정 단위 차단** — 지금은 IP마다 차단해요. 공격자가 IP를 바꾸면 우회할 수 있어요. **같은 아이디에 실패가 많으면 그 아이디를 잠그는** 기능을 추가해 보세요.
4. **⭐⭐⭐ 어려움: 취약점 하나 더 만들기** — 게시판 기능에 **XSS**(글에 스크립트 넣기)를 일부러 넣고, 그다음 출력할 때 **이스케이프**로 막아 보세요.
5. **⭐⭐⭐ 어려움: 보안 헤더 점검기 만들기** — 서버 응답 헤더를 읽고 `X-Content-Type-Options`가 없으면 경고하는 도구를 만들어 보세요.

## 🧠 이 실습에서 배운 보안 원칙 5가지

1. **입력은 믿지 않는다** → 2단계의 SQL 인젝션
2. **비밀번호는 원문으로 저장하지 않는다** → 해시와 소금
3. **무한정 시도하게 두지 않는다** → 요청 제한
4. **오류를 자세히 보여 주지 않는다** → 정보 노출 방지
5. **기록을 남기고 지켜본다** → 로그와 감시

## ✅ 스스로 점검 퀴즈

1. `admin' --` 입력이 로그인에서 비밀번호 검사를 건너뛰게 만드는 이유는?
2. `secure_app.py`에서 같은 공격이 `400`으로 막히는 두 단계는 어디인가요?
3. 보안 서버가 공격을 막았는데도 로그에 기록을 남기는 이유는?
4. 해시를 쓰면 DB가 털려도 안전한 이유를 한 문장으로 설명해 보세요.
5. 공격 도구에 127.0.0.1 제한을 둔 이유는?

<details>
<summary>정답 보기</summary>

1. `--`는 SQL에서 "뒤는 주석"이라는 뜻이에요. 그래서 `AND password = ...` 부분이 무시돼요.
2. 첫째, 입력 형식 검사(허용 글자만 받기)에서 막혀요. 둘째, 설령 통과해도 매개변수 쿼리 때문에 명령어로 해석되지 않아요.
3. 막힌 시도도 공격 흔적이에요. 누가 얼마나 자주 시도했는지 알아야 대응할 수 있어요.
4. 해시는 한 방향으로만 바뀌는 지문이라서, 저장된 값으로부터 원래 비밀번호를 쉽게 되돌릴 수 없어요.
5. 실수나 악용으로 남의 서버에 공격이 가는 것을 막기 위한 안전장치예요. 실습은 내 컴퓨터 안에서만!

</details>
